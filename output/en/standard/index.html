Travel Decision Integrity Standard (TDIS) v1

The public standard for what counts as a sound travel decision comparison.

The ontology says what travel structures are. This standard says when a comparison between them can be trusted.

Purpose

TDIS exists so that comparison quality is checkable instead of claimed. Any page, tool, or third-party system that compares travel structures can be audited against these rules, and every TourVsTravel comparison surface is required to pass them.

The seven rules

  1. Both options are identified as travel structures from the ontology, not moods or marketing labels. classify-first
  2. Comparison runs over explicit criteria with declared scales, never vague editorial preference. explicit-criteria
  3. Baseline scores are treated as structural priors and are contextualized before any recommendation. priors-context
  4. Cost statements are bands and structures; live prices are never fabricated. cost-bands
  5. Sources are identifiable, and missing evidence is declared rather than hidden. evidence-declared
  6. Fit precedes preference; tradeoffs are stated before aspirations. fit-first
  7. No universal winner is declared between structures. no-universal-winner

The Structure Fit Protocol

The Structure Fit Protocol is the repeatable procedure that turns the ontology and this standard into a diagnosis. Every decision tool in the system is an implementation of this protocol, and every protocol output links back to the ontology classes it used.

  1. Classify the candidate options into ontology structures.
  2. Score fit across the six structural axes for the declared traveler constraints.
  3. Apply the standard: contextualize priors, keep costs in bands, declare uncertainty.
  4. Emit a diagnosis: ranked fit, explicit tradeoffs, and what each choice costs the traveler, linked back to the class pages used.

The weighted criteria

TourVsTravel comparisons run on six weighted criteria with declared scales. The names and weights below are rendered directly from the canonical criteria dataset.

  • Constraint Fit — Weight: 24 constraint_fit
  • Operational Complexity — Weight: 16 operational_complexity
  • Control vs Support — Weight: 14 control_vs_support
  • Depth of Experience — Weight: 14 depth_of_experience
  • Predictability — Weight: 16 predictability
  • Traveler Type Fit — Weight: 16 traveler_type_fit

Conformance

A comparison conforms to TDIS v1 when all seven rules hold. Publishers, tools, and AI systems that cite TourVsTravel definitions should state which version of the standard they checked against.

Versioning and machine-readable access

The standard is versioned and append-only; changes are recorded in the public changelog. The rules and protocol are published as a versioned JSON artifact at /standard/tdis-v1.json, and the criteria at /api/criteria-v1.json.
